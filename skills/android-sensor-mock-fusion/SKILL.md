# 模拟传感器注入：融合一致性与真实放行

适用：定位/路线模拟模块注入传感器后，目标 App 的方向指针异常（间歇大角度旋转、反向绕一圈、漂移）。

## 步骤

1. 枚举目标 App 的**真实注册**，别只看模块自己的 `registerListener` 日志：`adb shell "dumpsys sensorservice | grep -B2 -A6 <pkg>"` 输出「传感器名 + 监听类名」，含第三方 SDK（高德、广告 SDK）的 listener，比模块日志更全。模块自身的注册日志可直接当快查用，且**默认就在写**（`FakeLoc.enableDebugLog` 默认 true，不要先去翻 App 调试开关或 prefs 文件）：`adb shell "su -c 'grep -a \"registerListener: type\" /data/adb/lspd/log/verbose_*.log | grep -a <pkg> | sed \"s/.*registerListener/registerListener/\" | sort | uniq -c'"` 一次给出该包注册过的全部类型及次数。完成：列出该 App 全部活跃传感器类型，标出不在模块注入集合里的项——它们就是**真实数据放行**。

2. 把「融合族」全部纳入同源注入——它们是同一虚拟姿态/方位的不同表现形式，必须同 tick 派生：加速度计、未校准加速度计、线性加速度、重力、磁力计、未校准磁力计、陀螺仪、未校准陀螺仪、旋转矢量、游戏旋转矢量、地磁旋转矢量、方向。完成：注入集合覆盖步骤 1 列出的全部融合族类型。

3. 族内取值同源：加速度计/重力 = 平放 `[0,0,9.81]`、线性加速度 `[0,0,0]`、磁力计按虚拟方位算水平指向、陀螺仪 = 方位变化率。只注入磁力计/旋转矢量而放行真实加速度计时，App 的 `getRotationMatrix(真实 accel 倾角, 注入 mag)` 会把真实设备姿态灌进投影，方位突变。完成：App 任取族内任意组合融合，结果都指向虚拟方位。

4. 方位角平滑趋近必须做环绕归一（易漏，症状 = 指针朝反方向绕一大圈才到目标）：差值先归一化到 [-180,180] 再乘趋近系数，平滑值自身与最终输出都 mod 360 到 [0,360)。跨 0/360 边界（如 350°→10°）不归一时线性差值为 -340°，平滑值走长弧。完成：跨北向的目标切换走最短弧，输出恒在 [0,360)。

5. 路线/路径播放的指针乱转：折线端点直接切换 = 方向瞬转。解法 = 被标记为平滑的线段整段替换为三次贝塞尔曲线（播放沿曲线采样点走，方向连续变化）：起点切线 = 前一条直线的无平滑几何方位（首段用自身方位）、终点切线 = 后一条直线方位（末段用自身方位）、控制点偏移 = 段长/3（Hermite，C1 连续、曲率平缓无突变）、沿曲线按 ~1m 采样。参照角一律取原始直线方位，平滑段之间不互相耦合。完成：平滑段播放时方向随曲线连续渐变，无突发曲率变化。

6. 播放推进按弧长算目标点、直接设位置，不要「盲推 + 检测是否到达点位」：路径构建时给每个采样点记累计距离（cum），每 tick `已走 += 速度 × tick秒`，用单调游标在路径上线性插值出本 tick 坐标后 `setLocation`，走满总长即精确落终点收尾。盲推检测在密集采样点（~1m/点）上会被到达阈值批量跳点、整条平滑段瞬间走完（症状 = 平滑段播放异常快）；把阈值改成「点间距一半」也只是打补丁。完成：平滑段与普通段播放速度都等于设定速度，曲线匀速无跳点。
   改成直连 `setLocation` 时**必须同时显式下发方位**（`update_location` 附带 bearing → 系统侧 `setBearingSlew` 直接采用）：位置注入的位移推算方位带「单次位移 ≥1m 才更新」门控，弧长步长 ~0.2m/tick 永远触发不了，方位冻结后的症状是**朝向固定在一侧摆动、不随路线转向**（看着像扰动算法问题，实为方位源冻结）。切线取「向前 ~2m 前视点」的方向，前视查询用独立游标、不推进位置游标。完成：路线转弯时朝向跟随切线连续转向，与位置同步。

7. 自动播放器状态只用**单一状态源**（悬浮摇杆的自动播放标志）驱动：播放循环每 tick 只判断该标志，关闭时空转、开启时从重置态开始。不要用 pause/resume 通道——循环内因「未选路线/定位未就绪」`pause()` 等待 `resume()`，而 resume 只由 UI 开关发出，之后选路线也不会恢复（症状 = 播放彻底失效）。循环重建判断用 `!job.isActive`：正常结束的协程 `isCancelled == false`，用它判断会让播完一次后同一会话再也无法重播。同时保证**单写者**——自动播放期间手动摇杆循环与摇杆角度回调都不再写位置/方位（双写 + 朝向抢占的症状 = 碰一下摇杆播放就乱/失效，看着像随机故障）。选中路线时走一个集中重置函数（重建路径、累计距离、游标、起点定位标志），**重选同一条路线也重置**：否则 `cachedRoute === selected` 不重建，位置被挪到起点后下一 tick 又被拽回旧进度。完成：碰摇杆不打断播放；停播/播完后再次点播放都从起点重播；换路线与重选同条都从该路线起点开始。

8. 生效验证：模块侧（xposed）改动需 `adb reboot` 或 force-stop 目标进程后重测，仅 App 侧改动重装 APK 即可。
