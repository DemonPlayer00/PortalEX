## 一、装好之后先做三件事

1. **编译安装**：本项目不发布 APK，自行编译（见 [README](../README.md) 的 Build 一节）。
2. **在 LSPosed 里启用模块并勾选作用域**：
   - 勾选 **系统框架**（`android`）⇒ 定位与外周传感器都在**系统层**被替换，
     作用域外没有勾选的应用同样能拿到模拟数据；
   - 想让某个应用"额外"被处理时再单独勾它（多数场景不需要）。
3. **首次打开 App 并授权**：定位、**悬浮窗**（要用移动摇杆就必须给）、通知。

> 长跑/无人值守场景，顺手把「设置」页的 **电池优化白名单** 加上、必要时开 **后台保活**。

---

## 二、三分钟上手

1. 打开 App，停在 **Home**（地图页）；
2. 用**搜索**找地点，或**单击地图**选点（单击即落标记并反查地址；**长按**弹出该点的详情与操作），
   也可以从「历史位置」里挑一个；
3. 点 **启动模拟**（Location Mock / Route Mock / Gnss Mock 页底部都有同一个按钮，
   显示为「启动模拟 / 停止模拟」）；
4. 地图上的位置开始按你的设定走；打开目标应用即可看到同一份数据；
5. 结束时再点一次同一个按钮（变成「停止模拟」）。

## 三、页面导览

| 页面 | 用途 |
| --- | --- |
| **Home** | 地图选点、搜索、历史位置、镜头跟随、普通图/卫星图切换 |
| **Location Mock** | 选点后启动模拟；位置相关的核心操作 |
| **Gnss Mock** | 星图与卫星信息、AGPS/NMEA/地理围栏等功能开关、随机化卫星信息 |
| **Route Mock** | 选择/管理路线，沿路线自动行驶 |
| **Stamina Mock** | 体力模拟（跑动衰减、疲劳降速、恢复），参数与曲线 |
| **Cadence & Acceleration Mock** | 步频侧外周模拟的开关、波动强度、随机区间、当前步频读数 |
| **Angle & Compass Mock** | 角度与指南针侧外周模拟的开关与波动参数、当前注入档位回显 |
| **Setting** | 速度/海拔/精度、上报间隔、融合定位处置、抗回拉与保活、调试模式 |
| **Calibration** | 各路传感器噪声档（逐轴 σ、陀螺零偏）与**一键校准** |
| **Test** | 自检页：模拟状态、注入计数、普通应用视角的真实订阅读数 |

## 四、功能教程

### 4.1 选点与启动模拟

- **搜索**：按名称/地址搜索，选中后跳到该点；也能直接手填经纬度。
- **地图交互**：**单击**地图即落标记并反查地址；**长按**弹出该点的详情与操作。
- **历史位置 / 保存位置**：常用点位存下来，之后一键跳转。
- **启动模拟**：从这一刻起，系统给出的位置就是你设定的位置；
  **停止模拟**后立刻回到真实定位。
- 位置相关的可调项都在「Setting」页：**定位海拔**、**定位精度**（模拟的抖动范围）、
  **摇杆速度**、**位置上报间隔**（默认 100 ms，改完**重启模拟生效**）。

### 4.2 移动摇杆（手动走）

1. 先 **启动模拟**（未启动时点摇杆会提示"请先启动模拟"）；
2. 去 **Route Mock 页勾选「移动摇杆」**，屏幕边缘出现悬浮圆盘；
3. 拖动圆盘的方向柄 ⇒ 位置按该方向持续前进，**朝向自动跟随移动方向**；
4. 再次取消勾选即关闭悬浮窗（关闭时会一并停止推进）。

要点：

- 摇杆是**单实例**的，位置模拟 / 路线模拟共用同一个悬浮窗，**跨页面状态一致**；
- 需授予**悬浮窗权限**，否则点了没反应（会提示"请授权悬浮窗权限"）；
- 速度就是「Setting → 摇杆速度」，路线播放与摇杆使用同一套速度口径；
- 圆盘上还有一圈图标按钮：**展开菜单**（控制图标）里依次是
  **移动 / 自动**两组，以及 **自动播放** 与状态回显（见下节）。

### 4.3 路线模拟（自动走）

1. **Route Mock** 页选择一条路线（或先用绘制功能创建：开始绘制路线 → 逐点落笔，
   可切换**平滑绘制**、撤回上一点、完成路线）；
2. 点 **启动模拟**，并在 Route Mock 页勾选 **移动摇杆** 让悬浮圆盘出现；
3. 在圆盘上点 **展开菜单**（控制图标）→ 点 **自动**（机器人图标）展开自动卡片 →
   点 **自动播放**：位置即沿路线前进，转弯处**限角速度平滑转向**（不是折线硬拐），
   速度与摇杆口径一致；
4. 路线跑完会有**提示音 + 振动**；历史路线可复用、可删除。

常用搭配：路线 + **体力模拟** ⇒ 长距离跑动时速度会随时间自然起伏（见 4.6）。

### 4.4 传感器模拟（外周传感器）

**是什么**：在系统框架层伪造**外周传感器**（步频、加速度、陀螺、磁场、朝向等）。
目标应用不需要进入作用域，连走 NDK 的消费者也拿到同一份数据。
事件由模块自己生成，**不依赖设备底层传感器是否在工作**。

> ⚠️ 代价（也是检测面）：会话运行期间，**被接管的那一类**事件全部来自模块自产的虚拟世界，
> 真实晃动不会体现在这些传感器上。各传感器之间仍然自洽。

#### 两个开关，各管一侧

| 页面 | 开关 | 接管内容 |
| --- | --- | --- |
| Cadence & Acceleration Mock | 外周传感器模拟（步频侧） | 步数计数器 / 步数检测器 |
| Angle & Compass Mock | 外周传感器模拟（角度与指南针侧） | 加速度（含未校准/线性）、陀螺（含未校准）、磁场（含未校准）、朝向/旋转矢量/重力 |

- 两者**默认都开**；关掉一侧后，那一侧**一个事件都不会被替换**（真实值原样透传）；
- 两个开关互不影响：只开一侧时，另一侧照常是真实传感器；
- 开关**点了即生效**，失败会明确弹提示（不会"看起来关了其实还在注入"）。

#### 波动强度 / 随机区间（默认各 15%）

两组各有两条参数，让模拟数据不像"机器生成的完美值"：

| 参数 | 作用 | 默认 |
| --- | --- | --- |
| **波动强度** | 慢漂幅度：读数在**秒级**上缓慢来回走 | 15% |
| **随机区间** | 逐条随机：**每条事件**在 ±该比例内抖动 | 15% |

- 两条都填 **0 = 关闭**（回到"不抖"的原始输出）；
- 步频侧作用于**步间隔** ⇒ 表现为步频一段快、一段慢，每一步还略有参差；
- 角度与指南针侧按各传感器的**参考量**折算（加速度/重力/线性 = 1g、陀螺 = 1 rad/s、
  磁场 = 50 µT、方向角 = 180°），所以数值偏小的传感器（如静止的陀螺）也会真的抖起来；
- 旋转矢量的抖动加在**转动角**上，四元数仍是单位四元数（姿态类应用不会跑偏）。

#### 噪声档与一键校准（Calibration 页）

- 这里是**另一层**：逐轴**本底噪声 σ**（陀螺还多一项零偏 μ）。σ 越大越抖，σ = 0 = 该轴完全不抖；
- **一键校准**：把手机放在平稳表面**静止 8 秒**，按 50 Hz 采集本机真实噪声并自动填表
  （检测到移动会作废重来）；**校准必须在"模拟未运行"时做** —— 模拟一跑，
  框架侧就在压制真实传感器，采到的只会是模块自己生成的数据；
- 「恢复默认」回到内置的通用量级。

#### 怎么确认真的生效（推荐看一眼 Test 页）

Test 页「注入计数（原生层）」一栏会显示被接管类型的事件与压制计数、当前下发档位；
「普通应用视角」一栏是本进程**真订阅**到的步数/间隔读数 —— 那是普通计步应用会看到的东西。

### 4.5 GNSS 模拟

- **Gnss Mock** 页：星图、可用/在用卫星数量、平均信号强度、选中卫星详情（PRN/信号强度/仰角/方位角）、
  导航系统计数、位置精度；
- **随机化卫星信息**：让卫星分布与强度不那么规整；
- **功能设置**：允许地理围栏请求、允许位置获取、启用 AGPS 模块、启用 NMEA 模块
  （NMEA 为数据流输出，供需要原始报文的应用）；
- 「Setting → 模拟最少卫星数量」控制参与模拟的最少卫星数（**只支持北斗**；
  默认 12 颗）。

### 4.6 体力模拟（长跑更像真人）

「Stamina Mock」页一眼看懂：

- **启用体力模拟**后，速度会随体力变化：跑动消耗、空闲恢复，体力过低进入**疲劳**并降速，
  冷却到阈值后重新开跑；
- 页面上的**参数（点击修改）**包括：体力衰减、疲劳体力值、开跑阈值、过渡时间、恢复速度、
  疲劳时速度、跑动降速下限、**随机化幅度**（默认 ±15%，让每次衰减/过渡/疲劳时长都不一样）、
  忽略窗口与忽略阈值（异常速度不计消耗）等；
- **理论 / 生成**两个页签：前者是解析曲线（含 ±随机包络），后者是真实引擎跑出来的一条实际曲线；
- 「这套参数跑出来」会直接算出首次疲劳距离、一次疲劳时长、周期、疲劳时速度等，方便调参；
  参数不健康时页面会给出明确告警（例如衰减过高导致一路掉到 0）；
- 「重置体力 / 重置数据」分别是清空当前体力与恢复出厂参数。

### 4.7 融合定位处置（`fused` provider）

「Setting → 融合定位处置」三选一：

| 取值 | 含义 |
| --- | --- |
| **伪装**（默认） | 让系统融合定位照常计算，但最终结果换成模拟位置 —— 兼容性最好 |
| 放行 | 不干预融合结果（部分设备上会与模拟位置"打架"） |
| 拒绝 | 直接拒绝对融合 provider 的请求 |

### 4.8 位置被"拉回"怎么办

真实设备上某些应用/系统服务会用别的来源把位置拽回真实值。三个开关按需开：

- **反定位拉回**：持续强力回推位置（效果最直接，代价是**可能发热**）；
- **禁用扫描 Wi-Fi 列表**：阻止应用扫描 Wi-Fi 列表（Wi-Fi 指纹是最常见的回拉来源）；
- **网络降级为 CDMA**：弱化网络定位通道。

另外「融合定位处置 = 伪装」通常也要配合着开。改动这些开关后建议**重启一次模拟**再观察。

### 4.9 抗冻结与保活

- **后台保活**：无人值守仍在走时，用前台服务把 App 钉住，避免被系统冻结导致位置停住；
- **电池优化白名单**：点一下申请系统豁免（设置页会显示"已加入"）。

### 4.10 诊断（Test 页）

一页看全：模拟开关与会话状态、原生注入层装载/激活、事件计数与压制计数、
当前档位（噪声、按组波动）、应用期望频率、握手门禁、融合定位视角、
**普通应用视角的真实订阅读数**（步数、事件间隔、逐事件回调）、体力与推进状态、最终坐标。

排查问题时优先看这里：**页面上的数字比"感觉没生效"可靠得多**。

## 六、常见问题

**Q：目标应用还是显示真实位置？**
按顺序检查：① LSPosed 里模块已启用且勾选了**系统框架**；② App 里已点「启动模拟」；
③ 目标应用是否自己在用融合定位/网络定位 ⇒ 打开「融合定位处置 = 伪装」与「反定位拉回」；
④ 更新过模块 APK 之后请**重启设备**（或重启 zygote）再验证 —— 否则可能仍在用旧的模块实例。

**Q：位置老是"跳回去"？**
见 4.8：反定位拉回 + 禁用扫描 Wi-Fi 列表 + 融合处置伪装，必要时再叠网络降级。

**Q：步数不涨 / 传感器数值不动？**
① 先确认会话在跑（Test 页「会话运行中」）；② 确认对应一侧的开关是开的
（步频侧 / 角度与指南针侧各一个）；③ 静止时步数本来就不涨 —— 需要位置真的在移动
（摇杆或路线播放）；④ 看 Test 页「注入计数」有没有事件。

**Q：一键校准点了没反应/报错？**
校准要求**模拟未运行**且手机静止 8 秒。先把模拟停掉再校准。

**Q：改了参数没变化？**
「位置上报间隔」这类标注了"重启模拟生效"的项需要重启一次模拟；
传感器开关与波动参数是**即改即生效**的。

**Q：Setting 页有个 SELinux 开关，点了没任何变化？**
这是历史遗留项（当前版本不参与任何逻辑），可以忽略。

**Q：想看日志？**
打开「Setting → 调试模式」，然后用 `adb logcat -s PortalEX:*` 查看。
